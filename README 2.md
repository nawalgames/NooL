# موقع NoL — دليل التشغيل والنشر

لا أستطيع نشر الموقع لك مباشرة لأن ذلك يتطلب الدخول بحسابك الخاص على
Firebase (ولا أملك اتصال إنترنت من بيئتي هنا أصلاً). الخطوات التالية
تنشر الموقع فعلياً على استضافة Firebase المجانية (Spark plan) خلال
دقائق.

## 1) أنشئ مشروع Firebase
1. اذهب إلى https://console.firebase.google.com
2. أنشئ مشروعاً جديداً (مجاني).
3. من القائمة الجانبية: **Build → Realtime Database → Create Database**
   (اختر أي منطقة قريبة، وابدأ في وضع "Locked mode" — القواعد أدناه
   ستحل محله).
4. من القائمة الجانبية: **Build → Authentication → Sign-in method**،
   فعّل **Email/Password**.
5. من نفس الصفحة تبويب **Users → Add user**: أضف بريدك الإلكتروني
   وكلمة مرور — هذا حساب دخولك للوحة التحكم (`admin.html`).

## 2) اربط بيانات مشروعك بالملفات
1. في Firebase Console: **Project settings (⚙) → General → Your apps
   → Web app (</>)** — أنشئ تطبيق ويب، وانسخ القيم الظاهرة.
2. الصق نفس القيم في **كلا الملفين** `index.html` و `admin.html`،
   داخل المتغير `firebaseConfig` أعلى كود الجافاسكريبت.
3. افتح `.firebaserc` وضع معرّف مشروعك (Project ID) بدل
   `YOUR_PROJECT_ID` (تجده في Project settings أيضاً).

## 3) ثبّت أدوات Firebase وسجّل الدخول
```
npm install -g firebase-tools
firebase login
```

## 4) انشر الموقع
من داخل مجلد `nol` (هذا المجلد):
```
firebase deploy
```
هذا الأمر ينشر الملفات (Hosting) **وقواعد الأمان** (Database Rules)
معاً. بعد الانتهاء سيعطيك رابط الموقع المباشر (شكله عادة
`https://YOUR_PROJECT_ID.web.app`).

- الموقع العام: `https://YOUR_PROJECT_ID.web.app/`
- لوحة التحكم: `https://YOUR_PROJECT_ID.web.app/admin.html`
  (لا تشارك هذا الرابط علناً، ولوّن يعمل فقط بحساب الدخول الذي
  أنشأته في الخطوة 1)

لربط دومين خاص بك (مثل nol.com بدل web.app): **Hosting → Add custom
domain** في Console واتبع التعليمات هناك.

## 5) قواعد الأمان (database.rules.json) — ماذا تفعل
- **games / social**: أي شخص يقدر يقرأها (لعرض الموقع)، لكن فقط
  حسابك المسجّل (auth) يقدر يعدّلها — أي عبر لوحة التحكم فقط.
- **codes**: أي شخص يقدر يتحقق من كود موجود مسبقاً (هذا مطلوب ليعمل
  التفعيل من الموقع العام)، لكن لا أحد غير حسابك يقدر **ينشئ** كوداً
  جديداً من الصفر، ولا يقدر يغيّر اللعبة أو المدة المرتبطة بكود
  موجود، ولا يقدر "يسرق" كوداً مفعّلاً مسبقاً على جهاز آخر.

⚠️ هذه القواعد أساس جيد وتمنع الاستغلال البسيط، لكنها ليست بديلاً
كاملاً عن خادم خلفي (Cloud Functions) إن كبر المشروع لاحقاً — خصوصاً
لو أردت لاحقاً ربط الدفع تلقائياً بإنشاء الأكواد.

## الحد المجاني (Spark plan)
Hosting: 10GB تخزين تقريباً / 360MB نقل يومياً.
Realtime Database: 1GB تخزين / 10GB نقل شهرياً.
يكفي بسهولة لموقع بهذا الحجم؛ إن كبر لاحقاً يمكنك الترقية لـ Blaze
(دفع حسب الاستخدام) دون تغيير أي كود.

## ما الذي بُني حتى الآن
- `index.html` — الواجهة العامة: شبكة الألعاب + نافذة كود الاشتراك
  + صفحة الدعم/التواصل الاجتماعي.
- `admin.html` — لوحة تحكم محمية بتسجيل دخول (Firebase Auth):
  إضافة/حذف ألعاب، توليد أكواد اشتراك (أسبوع/شهر/سنة أو مدة مخصصة)،
  جدول تتبع كل الأكواد مع الحالة (جديد/نشط/منتهي/ملغى) وإحصائيات
  سريعة، وزر إلغاء كود.
- `database.rules.json` — قواعد أمان تمنع التلاعب بالأكواد والألعاب
  من خارج لوحة التحكم.
- `firebase.json` / `.firebaserc` — إعداد الاستضافة، جاهزة للنشر
  بأمر واحد بعد وضع Project ID.

## لم يتبقَّ ناقصاً بعد هذه الجولة
- الألعاب الفعلية نفسها (الروابط لا تزال تُضاف يدوياً من لوحة التحكم).
- ربط الدفع التلقائي بتوليد الكود (حالياً: تواصل يدوي عبر صفحة الدعم
  ثم توليد الكود يدوياً من لوحة التحكم).
- تنبيه للمستخدم قبل انتهاء اشتراكه.
- حسابات التواصل الاجتماعي الحقيقية (لا تزال placeholder في
  `index.html`، عدّلها يدوياً أو أضف مسار "social" في القاعدة).
